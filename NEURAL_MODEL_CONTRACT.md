# Контракт нейросети цифрового двойника

Этот документ описывает стабильный интерфейс встроенной нейросети и актуальный конвейер обучения PyTorch.

## Текущая архитектура

```text
последние 10 состояний × 25 входных параметров
→ LayerNorm(25)
→ GRU(input=25, hidden=64, layers=2)
→ Linear(64, 32) + ReLU + Dropout
→ Linear(32, 10)
→ вероятности 10 действий
```

Архитектура реализована в `digital_twin_game/torch_model.py`. Она содержит 44 892 обучаемых параметра, сохраняется в `models/personal_gru.pt` и используется финальным двойником. `digital_twin_game/neural_model.py` сохранена только как аварийная MLP, чтобы игра оставалась запускаемой при проблеме с CUDA или PyTorch.

Семь дополнительных способностей записываются как события повтора, но намеренно не расширяют первый контракт. Первая модель по-прежнему решает стабильную задачу `25 → 10`. После проверки базовой модели способности можно добавить отдельной головой классификации или расширить список действий во второй версии формата данных.

## Интерфейс

Модель наследует `ActionPredictionModel` из `digital_twin_game/model_interface.py` и реализует:

```python
def predict(self, features: Sequence[float]) -> Prediction:
    ...

def reset_history(self) -> None:
    ...
```

Требования:

- каждый вызов получает ровно 25 чисел, а модель внутри хранит последние 10 вызовов;
- каждое число находится в диапазоне `[-1, 1]`;
- на выходе ровно 10 неотрицательных вероятностей;
- сумма вероятностей равна 1;
- порядок входов и выходов нельзя менять.

## Данные

Каждая игровая сессия создаёт:

- `data/session_<id>.csv` — обучающие строки;
- `data/session_<id>.json` — схема, частота записи и баланс классов.
- `data/replay_<id>.json` — подробный повтор для разбора ошибок модели.

Помимо 25 входов и `action_id`, CSV содержит `player_id`, `arena_time`, `reward`, `damage_dealt`, `damage_taken`, `successful_block`, `perfect_dodge`, `effective_heal`, `kill`, `objective_progress` и версию схемы исходов. Старые CSV читаются в совместимом режиме и получают отдельный анонимный профиль.

`sequence_data.py` по возможности делит выборку по игрокам в пропорции примерно 70/15/15: все сессии одного человека целиком находятся только в одной части. При недостатке реальных профилей используется совместимое разделение целыми сессиями. Редкие классы (`HEAL`, `BLOCK`, `DASH`) балансируются через `WeightedRandomSampler`.

Общая GRU обучается на других игроках, затем измеряется на текущем человеке и дообучается на его ранних сессиях. Оценка включает loss, accuracy, macro-F1, матрицу ошибок и примеры ошибочных моментов. История метрик сохраняется в `models/metrics_history.json`.

Завершающий offline-RL этап использует записанную во время боя ограниченную награду: нанесённый и полученный урон, успешные блоки, идеальные уклонения, эффективное лечение, убийства и прогресс задания. Для старых записей остаётся контекстная эвристика. KL-штраф и imitation-якорь не дают модели резко отойти от поведения игрока; обновление отклоняется, если контрольная точность падает более чем на 3 процентных пункта.

Перед обучением `data_quality.py` проверяет объём данных, покрытие классов, повторы и долю строк с настоящими наградами. Игра показывает недостающие действия, а калибровочные испытания специально собирают блоки, рывки, уклонения и лечение. Обучение запускается в фоновом потоке, поэтому главный цикл Pygame не блокируется.

## Подключение к игре

После реализации модель передаётся игре как объект `ActionPredictionModel`:

```python
from digital_twin_game.game import DigitalTwinGame
from my_neural_model import MyNeuralModel

DigitalTwinGame(action_model=MyNeuralModel("models/twin.pt")).run()
```

Если объект модели не передан, автоматически используется явно подписанный `PlaceholderPredictor`. Контроллер двойника получает результат через тот же метод `predict()` и может использовать два режима:

- копирование наиболее вероятного действия;
- выбор контрдействия против предсказанного действия игрока.

Нельзя давать двойнику прямой доступ к текущим нажатиям клавиш: прогноз должен строиться только по 25 признакам.
